# medifee.keywordegg.com

건강보험이 적용되지 않는 **비급여 진료비**를 항목별·지역별·병원 종별로
보여주는 사이트. yoyang·sanhu 와 같은 스택(Next.js + Supabase + Cloudflare)과
같은 UI 스킨을 쓴다.

---

## 이 사이트가 말하는 것과 말하지 않는 것

**금액을 그대로 싣는다.** 자료가 2025년 것이기 때문이다.

말하지 않는 것은 **병원별 가격**이다. 원본이 집계 통계라 한 항목에 대해
그 지역·종별의 최저·최고·평균·중간값 네 값만 있다. "서울 A병원 도수치료
얼마"는 이 자료로 알 수 없고, "서울에서 도수치료가 어느 범위인가"만 알 수 있다.

그래서 화면은 **중간값을 앞세운다.** 최저·최고는 한 곳만 있어도 잡히는 값이라
대표성이 없다 — 도수치료 최저가 300원으로 잡히는 것이 그런 경우다.

> 처음에는 공공데이터포털 15001700 을 썼다. 병원별 자료라 더 좋아 보였지만
> **가격 적용일자가 2015년(92%)·2016년(8%)** 이었다. 10년 전 가격을 현재
> 가격처럼 보이게 만들 수 없어 버리고 KOSIS 로 갈아탔다.

## URL 구조

| 경로 | 화면 |
|---|---|
| `/` | 홈 — 많이 찾는 항목, 종별 차이, 격차가 큰 항목 |
| `/항목` | 항목 허브 (668개 / 대분류 65개) |
| `/도수치료` | 항목 상세 — 지역 17 × 종별 10 금액표 |
| `/지역` | 시도 허브 (17개) |
| `/서울` | 시도 상세 — 항목별 금액, 전국 대비 |
| `/종별` | 병원 종별 허브 (10개) |
| `/의원` | 종별 상세 — 항목별 금액, 전체 종별 대비 |
| `/비급여-뜻` 외 3편 | 가이드 |
| `/about` `/contact` `/privacy` `/terms` | 안내 |

`app/[slug]/page.tsx` 하나가 이 모두를 맡는다.
**고정 슬러그(허브·시도·종별·가이드)를 항목보다 먼저 찾는다.** 항목 슬러그는
원본 데이터에서 나오므로 순서를 뒤집으면 새 항목 이름이 `/의원`이나 `/서울`을
가릴 수 있다. 적재 스크립트의 `RESERVED` 목록이 애초에 그런 슬러그를 만들지
않게 막는다 — 양쪽을 함께 고칠 것.

## 데이터

KOSIS **354_001** 「비급여진료비용및제증명수수료통계」(건강보험심사평가원)
<https://kosis.kr/statHtml/statHtml.do?orgId=354&tblId=DT_354006_2021A022>

시도별 17 × 2 + 병원 종별 10 × 2 = **통계표 54개**를 모은다. 축마다
"비급여 진료비용"과 "제증명수수료" 표가 따로 있어 두 배가 된다.

```bash
npm run probe:kosis      # 표 하나만 받아 구조 확인
npm run import:kosis     # 54개 표 전체 적재 + 집계 갱신
npm run import:kosis -- --dry-run
```

`KOSIS_API_KEY` 가 필요하다. <https://kosis.kr/openapi/> 에서 따로 발급받는
키이며 **data.go.kr 키와 다르다.**

### 실측으로 확인한 것

| 항목 | 값 |
|---|---|
| 적재 행 | 12,645건 (54개 표, 원자료 50,604행을 접은 값) |
| 항목 | 668개 / 대분류 65개 |
| 축 | 시도 17 + 병원 종별 10 |
| 기준 연도 | **2025년** (통계표 갱신 2025-11-19) |
| 통계값 | T001 최저 · T002 최고 · T003 평균 · T004 중간 |

### 항목 코드에 있는 함정

**같은 코드가 표 종류마다 다른 뜻이다.** `A0101` 이 비급여진료비용 표에서는
1인실이고 제증명수수료 표에서는 일반(진단서)이다. 이렇게 겹치는 코드가 16개다.
그래서 항목의 고유키에 `fee_kind` 가 반드시 들어간다
(`unique (fee_kind, item_code, scope_type, scope, year)`).

### 슬러그 규칙

기본은 **상위 분류 + 이름**(`/증식치료-척추부위`)이다. 이름이 유일하고 그것만
으로 뜻이 통하며 상위 분류가 대분류와 같을 때만 이름 하나로 줄인다
(`/도수치료`, `/1인실`). "일반"은 46번, "3주 미만"·"1~5매" 같은 수량 표기는
떼면 뜻이 사라지므로 줄이지 않는다.

MRI 표만 예외다. 항목 이름에 "MRI" 가 없어서 — "뇌 일반"이 뇌 MRI다 —
이름과 슬러그 양쪽에 붙여 준다(`/mri-뇌-일반`).

## 지켜야 할 원칙

- **집계값임을 반복해서 밝힌다.** 병원 한 곳의 가격으로 읽히면 사이트가
  거짓말을 하는 셈이 된다. `DataNotice` 가 모든 화면 하단에서 그 역할을 한다
- **중간값을 앞세운다.** 최저·최고는 한 곳만 있어도 잡힌다
- **기준 시점을 노출한다.** 자료가 2025년이라는 사실이 화면마다 있어야 한다
- **가격 차이를 품질 차이로 말하지 않는다.** 의료광고로 읽힐 여지를 만들지 않는다
- **병원을 추천하거나 순위를 매기지 않는다.** 심평원처럼 분포만 보여주고 판단은 넘긴다
- **확인하지 않은 숫자를 쓰지 않는다.** 실손 자기부담률, 본인부담상한액처럼
  해마다 바뀌는 값은 구조만 설명하고 공식 창구로 넘긴다

## 개발

```bash
npm install
npm run dev
npm run lint && npm run build
npm run export:urls              # naver-indexing/urls.txt
npx wrangler login && npm run cf:deploy
```

Supabase 는 keywordegg 계열과 같은 프로젝트를 쓰고 테이블 접두사(`medifee_`)로만
나눈다. 애드센스 퍼블리셔도 같은 계정이라 재승인이 필요 없다.
슬롯만 이 사이트용으로 만들어 `lib/ads.ts` 에 넣으면 된다.
